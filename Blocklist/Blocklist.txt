# =============================================================================
#  PrivACR ACR Blocklist
#  Smart-TV Automatic Content Recognition (ACR) endpoints
# =============================================================================
#
#  Source: "Watching the Watchers: Privacy Analysis of U.S. Smart TV
#          Automatic Content Recognition"
#
#  Covers the second-party ACR endpoints validated across the eight dominant
#  U.S. smart-TV operating systems (~95% market). Blocking these domains
#  suppresses ACR viewing-history collection at the network layer, including
#  on platforms where the on-device opt-out is ineffective (e.g. Samsung
#  Tizen, Vizio SmartCast).
#
#  HOW TO USE
#    Pi-hole / AdGuard Home : add this file as a custom blocklist (URL or
#                             local import). Wildcards work in AdGuard Home;
#                             for Pi-hole use the regex/exact entries.
#    /etc/hosts             : use the 0.0.0.0 lines below (exact hosts only;
#                             hosts files do not support wildcards).
#    Router / firewall      : block the second-level domains listed.
#
#  IMPORTANT CAVEATS
#    * Blocking ACR domains may disable "enhanced viewing" / content-based
#      recommendation features, but does NOT affect normal streaming/playback.
#    * The Amagi cleartext-DNS viewing-history leak (see bottom section) is
#      delivered over the SAME hostnames used for First-Party (FAST) channel
#      delivery. Blocking it BREAKS free streaming. It is listed separately
#      and is OFF by the recommendation; an OS-side fix is required.
#    * ACR operators rotate endpoints. Second-level-domain / wildcard rules
#      are more durable than the point-in-time exact hostnames.
#
#  Confidence tiers:
#    [VALIDATED] endpoint confirmed by the paper's four-indicator methodology
#    [SUSPECTED] strong supporting evidence, no payload-level confirmation
# =============================================================================
