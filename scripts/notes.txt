#### Filter Endpoints (Section 5)
Part of the methodology is to define the ACR endpoints for each smart TV through numerous filtering steps. This folder (and partly acr_behavior_analysis folder) provides the scripts for the filtering steps. Since the smart TVs contact a large number of endpoints and generate a large amount of network traffic, certain filtering steps take a considerable time. To skip this stage for our dataset, we also provide the .csv files for the traffic to/from the identified ACR endpoints, so that the analysis scripts can be run for those endpoints. Please see how to download the files using the script in Step 1, or you can find them in Google Drive link (https://drive.google.com/drive/folders/14AnQWI5DxC-03ya1vj1wfGKy54shhc4f?usp=sharing)

### ACR behavior analysis (Section 6)
To generate the time series and CDF figures for network traffic to ACR endpoints, the following commands are used. The analysis is completed on those figures to define the ACR activity and answer each research question.

How to interpret the results: Each plot is named with the experiment scenario and its experiment time. When we see high network activity to the ACR endpoint in the plots, it means that there is an ACR data transfer to the endpoint. Section 6.1 answers which scenarios are subject to ACR, which is defined from the observations in the plots. Section 6.2 analyzes the ACR opt-out efficiency. To interpret the results, one needs to examine the (ACR=OFF) plots. If there is high network activity in these plots, it means that the ACR opt-out is ineffective, while low or no network traffic means that the opt-out settings are effective. Section 6.3 answers the question of ACR modality for smart TVs. To interpret the results, one needs to compare the Antenna subscenarios. The Antenna 14.1 subscenario in our experiments is dynamic video but no audio, and the Antenna 10.1 subscenario is audio but black screen. When we see high traffic during Antenna 14.1, but low traffic during Antenna 10.1, it means that the modality is video ACR, and vice versa.


Please use one of the following for <os_name>: tizen, webos, roku_roku, roku_tcl, fire, smartcast

   python manager_analysis.py <os_name>

   python sony_manager_analysis.py google














The scripts for this project consist of two components: experiment control scripts and processing/analysis scripts. The experiment control scripts can be run with smart TVs of the same brand/OS as our inventory. The processing/analysis scripts can be run with the dataset we provide or with researchers' own network trace datasets.

1) Scripts to run experiments.
We developed control scripts for each smart TV, which allowed us to run automated large-scale measurements. To successfully run the experiments with each smart TV, the TV-specific parameters should be adapted. These include IP and MAC addresses, and app-specific algorithms (the navigation menu of each smart TV is different depending on how users place applications on the main menu).
